## Active

### M-022 — Engineering memory implementation frontier

Selected by: the completed source sequence through Q-07 and the user-directed
rapid implementation roadmap

Outcome: exact generator and assembly records become durable engineering memory
that the player can reset from, branch, compare, and transplant without losing
identity, evidence, or the distinction between organization and embodied
initial conditions.

Why now: M-020E and M-021 source packets establish addressed attempts, frozen
qualification, immutable results, and receipt-derived progression. The next
playable improvement is not another content contract. It is the ability to keep
successful and failed reasoning, make one deliberate revision, and see exactly
what changed. M-022A and M-022B now represent the record, migration,
Design-authority assembly, exact-capture, and interrupted-operation substrate in
source. The active frontier is M-022C: every state-reconstructing command must
consume that substrate through a typed preview, commit, receipt, persistence,
and recovery path before clone, comparison, or transplant may depend on its
lineage. Verification debt remains open under the active validation hold.

Implementation order:

1. **M-022A record authority and migration.** Define the immutable V2 generator,
   assembly, blueprint, derivation-edge, evidence-link, transition, diff,
   compatibility, adaptation, and comparative-result records before later
   commands depend on them. Upgrade browser storage additively, retain exact V1
   bytes and schema provenance, add a resumable migration journal, and give the
   volatile fallback the same add-if-absent conflict rules as IndexedDB.
2. **M-022B Design assembly transaction and exact capture.** Separate
   assembly-owned fields from generator-owned and runtime-only fields. Add a
   complete Design-only `AssemblyDraft`, Rust preview with exact compatibility
   and diff, stale-guarded commit, reconstructed opening, descendant branch, and
   Save Blueprint from committed Design or immutable result authority only. A
   commit may never alter generator bytes or silently promote live Commission
   positions, stocks, timers, damage, or transient policy state.
3. **M-022C named engineering transitions.** Replace the multiplexed reset
   mutation with preview, commit, and recovery operations for Restart Assembly,
   Revert Generator, and Full Contract Reset. Show exact retained, restored,
   recreated, and detached identities before confirmation; persist accepted
   branch closure and reconstruction by operation id; finish literal copy and
   three distinct reconstruction stances. Clone is not a reset because it
   creates a new attempt.
4. **M-022D clone lineage.** Clone an immutable blueprint, result source, or
   retained branch into a new editable attempt with true branch parentage,
   typed derivation edges, exact copied generator/assembly authority, an empty
   qualification slate, and a direct return to Design. Ancestor evidence remains
   shared read-only data.
5. **M-022E engineering diff and hypothesis branch.** Normalize each source into
   generator design, initial assembly, and observed evidence before deriving an
   address-aligned comparison across hardware, Routes, ordered rules, Route
   controls, stocks, material, compatibility, criteria, independent grades, and
   first-failure evidence. Let the player select one changed hypothesis and
   branch from either side without mutating the comparison sources.
6. **M-022F transplant compile and adaptation.** Compile compatibility for one
   byte-identical `GeneratorSpec` in a selected destination regime, permit only
   explicit Design-authority adaptation of assembly-owned fields, create a
   destination child attempt, and preserve incompatibility reports even when no
   run is created. Any required policy edit exits the unchanged-generator claim.
7. **M-022G comparative qualification.** Relate ordinary complete source and
   destination qualification results through one Rust-derived comparative
   record. Retain controlled and uncontrolled differences, matched identities,
   and the first addressed divergence without introducing a private paired
   qualifier or rewriting either result.
8. **M-024 companion integration.** Ship real-projection blueprints,
   operation-specific reconstruction, compact lineage, structural/policy diff,
   assembly change, and unchanged-machine/different-regime stances with their
   owning M-022 packet. No packet hands off with its only explanation in text.

##### E-05 execution contract: Restart Commission

The only M-020E reset is **Restart Commission**. Broader Restart Assembly,
Revert Generator, Full Contract Reset, clone, and transplant boundaries remain
owned by M-022 and must not be approximated with aliases.

The reset transaction is ordered and failure-aware:

1. **Read authoritative preview.** Rust resolves the active automation attempt,
   current branch and parent, current committed generator bytes/hash, contract
   opening assembly bytes/hash, scenario/regime, current step, next branch
   nonce, and resulting branch operation. React does not predict hashes or
   reconstruct the opening from catalog display data.
2. **Present consequences.** The confirmation names four independent effects:
   keep the committed generator, restore the contract opening assembly, retain
   the closing evidence, and create a child branch with a fresh RNG stream.
   Current and resulting identities are visible before confirmation.
3. **Prepare closure.** The shell asks Rust for the exact closing embodied hash
   and binds it to the current attempt/branch, retained event window, latest
   criterion vector, opening/closing steps, and `restart` closure reason. This
   prepared record is not yet published as closed evidence.
4. **Execute restart.** Rust reconstructs embodied state only from the named
   AssemblyTemplate, installs the unchanged committed GeneratorSpec, advances
   the nonce, creates an explicit child branch, clears branch-local runtime
   traces and criterion windows, and returns all resulting identities.
5. **Publish closure.** Only an accepted authoritative restart causes the old
   branch record and prepared evidence to be added immutably. A rejected
   command leaves the branch open and creates no closure. A durable-write
   failure retains the record in the volatile fallback and raises a visible
   degraded-durability state; it never retries by overwriting an existing id.
6. **Re-enter Design.** Selection may remain on an address that exists in the
   reconstructed machine; stale event and criterion selections clear. The
   player sees the new child branch and can inspect the restored opening before
   Commission resumes.

The confirmation has four UI states: `closed`, `previewing`, `ready`, and
`submitting`. A preview conflict, stale base identity, unsupported run kind,
closed branch, identity mismatch, core rejection, or archive failure receives
a distinct catalog-backed diagnostic. Double submission is suppressed while
the transaction is pending.

##### E-06 execution contract: Qualification input preview

E-06 is a read-only boundary, not an early qualification implementation. Rust
produces one canonical `QualificationInputPreview` from the live candidate and
the compiled ContractSpec. The preview contains:

- schema, content, build, protocol, run-kind, contract, attempt, source branch,
  parent branch, branch operation, and branch-nonce identities;
- complete canonical GeneratorSpec bytes/hash and complete canonical
  AssemblyTemplate bytes/hash, with exact versus migrated stance;
- scenario, regime/lawset, commissioning boundary, qualification-suite version,
  schedule identity, control contract, duration, trial addresses/count, seed
  custody description, early-resolution rules, and retention policy;
- the compiled criterion vector with address, unit, comparator, bound, window,
  grace, aggregation, trial aggregation, and criterion hash;
- four independent grade-axis definitions and the literal authored post-pass
  receipt, both clearly labeled as prospective rather than earned;
- a canonical preview identity plus a complete list of missing or incompatible
  inputs. A preview with any omission is `incomplete`, never `ready`.

The command is valid only for a paused automation candidate. It has no RNG,
step, branch, archive, progression, policy, topology, or embodied-state side
effect. Repeating it over identical authoritative inputs returns byte-identical
canonical content and identity. Wall-clock time and shell selection are absent.

The player surface has three states:

| State | Meaning | Available command |
|---|---|---|
| incomplete | one or more Q-01 inputs cannot be addressed exactly | inspect the literal missing-input list; Qualify disabled |
| ready to freeze | all inputs are exact, but the candidate remains editable and no request exists | review only; Qualify disabled until Q-01 |
| stale | the candidate identity changed after the displayed preview | refresh the preview; never submit the old identity |

The preview sheet shows exact identities first, trial procedure second,
criteria third, four independent grade axes fourth, and the prospective receipt
last. It does not use pass color, result framing, a seal, celebratory motion, or
language that claims readiness beyond “inputs complete.” Its M-024 stance keeps
the live machine editable and uses a restrained freeze-boundary marker around
the summary, not around the Field.

E-06 hands off to Q-01 when Q-01 can create its immutable request exclusively
from the preview's canonical inputs without consulting chapter/objective state,
React-authored defaults, a mutable browser summary, or unaddressed live state.
M-020E creates no qualification request, execution, result, grade, pass,
receipt, availability, or unlock record.

The engagement target for M-020E is a complete hypothesis loop under two
minutes: observe a weak margin, select the addressed object, inspect the rule
and observed physical outcome, change one rule or Route default, restart, and see the
first changed consequence within several authoritative steps. Retention is
valuable only when it helps answer "what changed and what did that alter?";
attempt history is not a generic activity feed.

#### M-023 — Advanced systems contracts

Before contract content begins, `S0-00 Evidence substrate` extends the closed
Rust criterion/source/unit vocabulary and qualification artifacts for per-output
service, reserve, purpose-typed upkeep, overload, signal/failover timing,
material use, reconstruction, and cross-regime comparison. The same packet adds
a versioned addressed mechanism-state/event vocabulary consumed by inspection,
rendering, audio, traces, and results. React receives projections only; it does
not compute a new metric, criterion, seal, or compatibility result.

Every advanced contract uses the same four-packet cadence before the next
contract begins:

1. `Sx-01 Opening and capability`: compile one canonical opening, capability
   envelope, construction limits, schedule, criteria, grades, and receipt.
2. `Sx-02 Authoritative pressure and minimum causal projection`: add only the
   minimum new Rust state and deterministic transition needed for the systems
   problem, including save, replay, inspection, events, analysis clones, exact
   Field projection, event localization, and distinct failure stances.
3. `Sx-03 Player loop`: add authoring, Commission diagnosis, contextual cues,
   qualification, result, blueprint, and reset behavior through shared systems.
4. `Sx-04 Causal fidelity refinement`: complete machine anatomy, transition
   timing, audio, narrow composition, renderer parity, and quality budgets for
   every new state, failure, and recovery. Sx-04 may refine a readable mechanic;
   it may not rescue a text-only Sx-03 player loop.

Sx-01 content and Sx-02 authoritative mechanics may be prepared while shared
engineering-memory work is settling, but no Sx-03 player loop integrates before
M-022C named transitions, M-022D derivation lineage, and M-022E normalized comparison are
available. M-023E additionally requires M-022F compatibility, adaptation, and
destination-instantiation boundaries. This prevents advanced contracts from
creating temporary reset, branch, diff, or transplant paths that would later
need migration.

| Contract | New decision space | Required authoritative evidence | Required causal expression | Source-level exit boundary |
|---|---|---|---|---|
| M-023A Balance | allocate finite source stock across competing service floors using Route limits and weights | per-output request/acceptance, shortage allocation, source residue, overload, and uninterrupted critical service | simultaneous split flow, visible allocation collars, source depletion, and branch-specific starvation | total flow cannot hide one failed output and no shell allocator exists |

The content ramp is mechanical, not narrative. Intake teaches acquisition;
Transfer teaches interfaces and acceptance; Buffer teaches temporal storage.
The first post-Buffer branch moves from Balance allocation to Closure's
loss-aware circulation; the second moves from Interference's local fault
inference to Renewal's distributed repair. Transplant joins the branches by
testing organization against environment, and Holdout tests robustness. Each
contract introduces one primary reasoning problem and reuses every earlier
primitive that remains relevant.

Implementation remains sequential so schemas stabilize in one place, but the
player-facing prerequisite graph creates choice after Buffer:

```text
Buffer
  |- Balance -> Closure ------|
  `- Interference -> Renewal -|-> Transplant -> Holdout
```

Balance and Interference become available from the same retained Buffer pass.
Transplant requires retained passes on Closure and Renewal. Holdout requires a
retained Transplant result. This is an engineering dependency graph, not a
campaign map; the ladder shows literal prerequisites and the exact retained
results satisfying them.

Every advanced contract content record also declares a tuning envelope:

- first disturbance or constraint step and the expected first visible
  consequence;
- first useful evidence-window target and maximum passive wall wait;
- dominant authored failure families and their exact diagnosis owner;
- named retry boundary and what it retains;
- at least two mechanically distinct passing architectures with different
  grade profiles;
- one unfamiliar primitive family maximum, with all reused primitives listed.

These fields prevent a 15-25 minute contract from becoming a longer timer or a
single hidden solution. They are content and pacing obligations; pass/fail still
comes only from the compiled criterion vector.

- Implementation always precedes new or updated validation. No TDD, ever.
- A later milestone may not silently absorb a missing dependency or strengthen a
  scientific claim beyond its evidence.
- Remote evidence cannot satisfy a target-Mac gate.
- A blocked direct inspection, credential, signing, or hardware gate remains
  visible in this ledger.
- Every completion row keeps its main commit, failed-run history, exact evidence,
  panel dissent, and next selection.
